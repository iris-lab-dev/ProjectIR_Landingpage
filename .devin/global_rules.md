# ProjectIR Landing Page Principles

## Brand core
- The central TUMTUM value is removing the friction before work begins: users should be able to start without quotes, chat, consultation, or comparison.
- Reuse this shared product promise where it is truthful: `견적 없이 · 채팅 없이 · 바로 시작`.
- Lead with the user's problem and resulting value, not feature names or platform mechanics.

## Requester landing
- The requester is the protagonist of the current request page.
- Core tension: small unresolved work stops the user's day.
- Core message: `작은 일이 당신의 오늘을 멈추지 않도록.`
- Statement pattern: `남기면, 바로 시작합니다.`
- The page should make the requester feel that they can leave the needed work and return to their own next task.

## Ad+
- Ad+ is a separate response-request product, not a subcategory of remote work or delivery.
- Its protagonist has already made or launched something; the problem is that their start lacks the reactions needed to continue.
- Treat confirmation, clicks, downloads, applications, and participation as examples of one response-request flow, not separate products that the user must choose between.
- Use `반응` as the user-facing value language. Use concrete actions only when explaining how a requested response is fulfilled or verified.
- Its key friction is starting advertising through sales calls, consultation, and product comparison. Keep the statement value centered on immediate start rather than on abstract reach.
- Current statement pattern: `필요한 반응을, 바로 시작합니다.` and `상담 없이 · 비교 없이 · 바로 시작`.

## Performer landing direction
- If a performer-focused landing is created, treat it as a separate product story from the requester page, even when it shares the same visual components and section rhythm.
- Do not center altruism or “helping someone else's day.” The performer’s primary motivation is finding work they can do now and receiving clear compensation.
- Define the performer problem as: a capable person has no suitable work available at the moment.
- Preferred hero direction: `할 수 있을 때, 할 일이 있도록.`
- Avoid making `수익` the hero keyword. Make compensation concrete in request details and explain it with `보상` where needed.
- Preserve the shared friction promise: `견적 없이 · 채팅 없이 · 바로 시작`.

## Apple-inspired product-page principle
- Apple-like consistency means sharing a design system and a disciplined narrative rhythm, not copying identical page content or UX without regard to the product.
- Each landing page must reflect the product’s own user state, motivation, and interaction model.
- Keep shared typography, spacing, buttons, and core section rhythm where the product logic aligns.
- Change the page’s message, examples, and emphasis when the user’s job differs: requester = resolve blocked work; Ad+ = start requested reactions; performer = find available work and compensation.
